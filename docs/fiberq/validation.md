# ვალიდაცია

v1.4.0-ის მთავარი სიახლე: **14 წესი**, რომელიც მთელ პროექტს ამოწმებს. შედეგი ორ ადგილას
ჩანს — ცოცხალ პანელში QGIS-ში და ექსპორტირებულ ანგარიშში.

## რატომ არსებობს

ანგარიშის ორი ვერდიქტი მთელ იდეას ერთ ფრაზაში ხსნის:

> `No errors — project is structurally sound`
> **შეცდომები არ არის — პროექტი სტრუქტურულად გამართულია**

> `Errors found — not ready to hand over`
> **აღმოჩენილია შეცდომები — ჩასაბარებლად მზად არ არის**

ანუ ეს არის **ჩაბარებამდელი შემოწმება**. „Hand over" — პროექტის ჩაბარება დამკვეთისთვის ან
ინსტანციისთვის.

## 14 წესი

წესის სახელი ინგლისურში იმ მდგომარეობას აღწერს, რომელიც **გავლისას სრულდება** — ანუ
მტკიცებაა, არა ბრძანება. ქართულიც ასეა.

### ტოპოლოგია და კავშირები

| # | წესი | ქართული |
|---|---|---|
| A1 | `Cable endpoints are connected` | კაბელის ბოლო წერტილები დაკავშირებულია |
| A2 | `Cable endpoints are not near-misses` | კაბელის ბოლო წერტილები ოდნავ დაცილებული არ არის |
| A3 | `Elements are attached to the network` | ელემენტები ქსელზეა მიბმული |

!!! info "რა არის „near-miss""
    ბოლო წერტილი, რომელიც **ოდნავ სცდება მიბმის დაშვებას** — არ არის დაკავშირებული,
    მაგრამ აშკარად უნდა ყოფილიყო. ეს A1-ისგან ცალკე წესია, რადგან სხვა პრობლემაა:
    A1 ამბობს „არაფერს არ უკავშირდება", A2 ამბობს „კინაღამ უკავშირდება".

### რეფერენციული მთლიანობა

| # | წესი | ქართული |
|---|---|---|
| B1 | `Optical slack references an existing cable` | ოპტიკური მარაგი არსებულ კაბელს მიუთითებს |
| B2 | `Fiber break references an existing cable` | ბოჭკოს გაწყვეტა არსებულ კაბელს მიუთითებს |
| B3 | `Cable references are spatially coherent` | კაბელზე მითითებები სივრცობრივად თანხვედრილია |
| B4 | `Feature identity present and unique` | ობიექტის იდენტიფიკატორი არსებობს და უნიკალურია |

B3 იჭერს იმ შემთხვევას, როცა ობიექტი **გეოგრაფიულად** დაშორდა იმ კაბელს, რომელსაც
მიუთითებს — შეტყობინება პირდაპირ ვარაუდობს მიზეზს: *„the cable may have been re-routed"*,
ანუ კაბელის ტრასა შეიცვალა.

### ატრიბუტები და დომენები

| # | წესი | ქართული |
|---|---|---|
| C1 | `Required attributes present` | სავალდებულო ატრიბუტები არსებობს |
| D1 | `Project contains FiberQ layers` | პროექტი შეიცავს FiberQ-ის შრეებს |
| D2 | `Attribute values within allowed domain` | ატრიბუტების მნიშვნელობები დაშვებულთა შორისაა |
| D2 | `Numeric attributes within plausible ranges` | რიცხვითი ატრიბუტები გონივრულ დიაპაზონშია |
| D3 | `Stored lengths agree with geometry` | შენახული სიგრძეები გეომეტრიას ემთხვევა |

!!! tip "`allowed` ≠ `plausible`"
    ორი მსგავსი წესია და ინგლისური განზრახ განასხვავებს: `allowed domain` = დაშვებულ
    მნიშვნელობათა **ჩამონათვალი** (მკაცრი), `plausible range` = **გონივრული** დიაპაზონი
    (რბილი შემოწმება). ქართულში `დაშვებული` და `გონივრული` ამ სხვაობას ინარჩუნებს.

### CRS და გეომეტრია

| # | წესი | ქართული |
|---|---|---|
| E1 | `Coordinate reference systems are consistent` | კოორდინატთა სისტემები თანხვედრილია |
| E2 | `Geometries are present and well formed` | გეომეტრიები არსებობს და გამართულია |

E2 ხუთ კონკრეტულ ხარვეზს იჭერს:

- `Feature has no geometry` — ობიექტს არ აქვს გეომეტრია
- `Line has zero length` — ხაზის სიგრძე ნულის ტოლია
- `Line crosses itself` — ხაზი კვეთს საკუთარ თავს
- `Polygon has zero area` — პოლიგონის ფართობი ნულის ტოლია
- `Polygon boundary is self-intersecting` — პოლიგონის საზღვარი კვეთს საკუთარ თავს

## CRS-ის ხაფანგი

E1-ის ერთი შეტყობინება ცალკე ღირს ყურადღებას, რადგან პრაქტიკული შედეგი აქვს:

> `Layer uses a geographic CRS ({crs}), where the connectivity tolerance is measured in
> degrees rather than metres`

**თუ შრე გეოგრაფიულ CRS-შია (მაგ. EPSG:4326), მიბმის დაშვება გრადუსებში იზომება, არა
მეტრებში.** ანუ „5 მეტრიანი დაშვება" სინამდვილეში 5 გრადუსია — დაახლოებით 550 კმ.

რჩევა თვითონ შეტყობინებაშივეა: *„Reproject to a national grid, or lower the tolerance to
a fraction of a degree."*

!!! example "საქართველოსთვის"
    ეს ნიშნავს UTM 37N / 38N-ს ან ეროვნულ სისტემას. FiberQ-ის სტრიქონი ზოგადია
    („national grid"), ქართული თარგმანიც ზოგადი დავტოვე — `ეროვნული საკოორდინატო ბადე`.

ასევე: **სიგრძის გაზომვა ელიფსოიდის გარეშე შეუძლებელია**. თუ პროექციული CRS-იც არ არის
და ელიფსოიდიც არ არის მითითებული, სიგრძის შემოწმება გამოტოვდება.

## სად ჩანს შედეგი

=== "პანელი (ცოცხალი)"

    `ValidationPanel` — dock QGIS-ში: ხუთსვეტიანი ცხრილი (სიმძიმე / წესი / შრე / ობიექტი /
    შეტყობინება), სამი ფილტრი, `ხელახლა გაშვება` და `ანგარიშის ექსპორტი` ღილაკები.

    სამი დონე: **შეცდომა** · **გაფრთხილება** · **ინფორმაცია**

=== "ანგარიში (ექსპორტი)"

    `ValidationReport` — დოკუმენტი ჩასაბარებლად: ვერდიქტი, ჯამები, გაშვების მეტამონაცემები
    (CRS, სქემის ვერსია, პლაგინის ვერსია, დრო), ხარვეზების ცხრილი და ხარვეზები შრეების
    მიხედვით.

    იმავე მენიუდან ხელმისაწვდომია **JSON და CSV** — მანქანურად წასაკითხი ვერსია.

!!! note "შვიდი სტრიქონი ორივეგანაა"
    `Severity`, `Rule`, `Layer`, `Feature`, `Message`, `Error`, `Warning` ორივე კონტექსტში
    მეორდება. Qt მათ ცალკე ინახავს — ანუ ქართულ თარგმანში ხელით უნდა გავაკონტროლოთ,
    რომ იდენტური იყოს, თორემ მომხმარებელი იფიქრებს, რომ სხვადასხვა მონაცემს უყურებს.
